# AutoClip 主播默认配置说明

> 适用目录: `configs\streamers`  
> 适用文件: `*.json`  
> 更新时间: 2026-09-08

主播默认配置用于给一键流转、GUI/Web 投稿清单生成和投稿模块提供默认参数。`core/auto_pipeline.py` 会根据录播目录推断主播名，并默认读取:

```text
configs/streamers/{主播名}.json
```

也可以通过命令行显式指定:

```powershell
python core\auto_pipeline.py -i "录播目录" --config "configs\streamers\主播.json"
```

## 1. 总体结构

推荐结构:

```json
{
  "streamer_name": "主播名",
  "version": 1,
  "description": "主播名 默认一键切片+投稿配置",
  "step1_prepare": {},
  "step2_subtitle": {},
  "step3_highlight": {},
  "step4_clip": {},
  "step5_burn": {},
  "step6_cover": {},
  "step7_upload": {},
  "bilibili_links": {},
  "keywords": []
}
```

根字段:

| 字段 | 类型 | 默认值 | 当前用途 |
| --- | --- | --- | --- |
| `streamer_name` | string | 文件名推断 | 主播显示名；步骤3 LLM 分析、步骤7 投稿标题前缀默认值会使用 |
| `version` | number | `1` | 配置版本标记，目前不参与逻辑判断 |
| `description` | string | 空 | CLI/配置工具显示说明 |
| `step1_prepare` | object | `{}` | 步骤1 录播文件准备（FLV 转 MP4、竖屏转横屏、弹幕压制、弹幕 XML→ASS） |
| `step2_subtitle` | object | `{}` | 步骤2 ASR 字幕配置 |
| `step3_highlight` | object | `{}` | 步骤3 高光分析配置 |
| `step4_clip` | object | `{}` | 步骤4 视频切片配置 |
| `step5_burn` | object | `{}` | 步骤5 字幕烧录配置 |
| `step6_cover` | object | `{}` | 步骤6 封面生成配置 |
| `step7_upload` | object | `{}` | 步骤7 投稿清单和投稿默认参数 |
| `bilibili_links` | object | `{}` | 投稿简介中追加主页/直播间链接 |
| `keywords` | array[string] | `[]` | 主播梗/关键词库；当前主要供配置、提示词和人工维护使用 |
| `llm` | object | `{}` | GUI 一键流转的 LLM Key/模型兜底来源；命令行流水线优先读 `configs/gui_config.json` |

## 2. 路径占位符

支持的常用占位符:

| 占位符 | 含义 | 典型字段 |
| --- | --- | --- |
| `{input_dir}` | 当前录播目录绝对路径 | `step4_clip.output_dir`、`step6_cover.output_dir`、`step7_upload.cover_rule` |
| `{timestamp}` | 切片文件名中的时间/segment 标记 | `step7_upload.cover_rule`，当前多数流程按实际文件名匹配封面 |
| `{title}` | 切片标题 | `step7_upload.cover_rule`，当前多数流程按实际文件名匹配封面 |
| `{summary}` | LLM 摘要 | `step7_upload.desc_template`，当前主流程改为从 `Data_source.txt` 自动拼接 |

注意: `cover_rule`、`title_rule`、`desc_template` 当前更多是配置说明/兼容字段。实际 `auto_pipeline.py`、`gui_app_mobile.py`、`web_console.py` 主要按切片文件名和 `Data_source.txt` 自动生成投稿清单。

## 3. `step1_prepare`: 准备录播文件

入口:

- `core/convert_flv_to_mp4.py`
- 可选 `core/convert_portrait_to_landscape.py`
- 可选 `core/burn_danmu_video.py`
- `core/convert_danmaku_xml.py`（弹幕 XML→ASS 前置转换，默认开启）

字段:

| 字段 | 类型 | 默认值 | 当前用途 |
| --- | --- | --- | --- |
| `recursive` | boolean | `false` | 递归扫描子目录中的 FLV/MP4/XML |
| `convert_flv` | boolean | `true` | 执行 1-1: FLV 转 MP4；旧配置未填写时默认执行 |
| `overwrite` | boolean | `false` | FLV 转 MP4 时覆盖已有 MP4 |
| `keep_flv_source` | boolean | `false` | FLV 转 MP4 成功后保留源 FLV |
| `portrait_to_landscape` | boolean | `false` | 执行 1-2: 竖屏 MP4 转横屏 1080p；横屏自动跳过 |
| `portrait_overwrite` | boolean | `false` | 已存在 `-竖屏原版.mp4` 备份时仍重新转换 |
| `delete_portrait_source` | boolean | `false` | 竖屏转横屏后删除原竖屏 MP4，不保留备份 |
| `landscape_width` | number | `1920` | 竖屏转横屏目标宽度 |
| `landscape_height` | number | `1080` | 竖屏转横屏目标高度 |
| `landscape_blur` | number | `20` | 背景模糊强度 |
| `burn_danmu` | boolean | `false` | 执行 1-3: 压制同名 MP4 + XML 弹幕版 |
| `burn_danmu_overwrite` | boolean | `false` | 弹幕版已存在时强制重压 |
| `overwrite_danmu` | boolean | `false` | `burn_danmu_overwrite` 的兼容别名 |
| `keep_danmu_ass` | boolean | `false` | 保留 DanmakuFactory 生成的 ASS 文件用于排错 |
| `convert_danmaku_xml` | boolean | `true` | 执行 1-4: 把与视频同名但缺同名 ASS 的 XML 弹幕转成 `.ass`，供步骤3弹幕分析使用；失败只提示不阻断 |

示例:

```json
{
  "step1_prepare": {
    "convert_flv": true,
    "recursive": false,
    "overwrite": false,
    "keep_flv_source": false,
    "portrait_to_landscape": false,
    "portrait_overwrite": false,
    "delete_portrait_source": false,
    "landscape_width": 1920,
    "landscape_height": 1080,
    "landscape_blur": 20,
    "burn_danmu": true,
    "burn_danmu_overwrite": false,
    "keep_danmu_ass": false,
    "convert_danmaku_xml": true
  }
}
```

步骤1执行顺序:

1. `convert_flv=true`: 扫描 `.flv`，用 FFmpeg stream copy 转成同名 `.mp4`；默认转换成功后删除源 FLV。
2. `portrait_to_landscape=true`: 扫描 `.mp4`，只处理竖屏视频；输出横屏画布并替换原 MP4，默认把原竖屏文件备份为 `原名-竖屏原版.mp4`。
3. `burn_danmu=true`: 匹配同目录同名 `.mp4` + `.xml`，输出 `原名-弹幕版.mp4`。
4. `convert_danmaku_xml=true`（默认）: 把与视频同名但缺同名 ASS 的 XML 弹幕用 DanmakuFactory 转成同名 `.ass`；已有 ASS 跳过，失败不阻断，XML 只读不改动。

竖屏转横屏规则:

- 横屏或方形视频自动跳过。
- 默认目标为 `1920x1080`。
- 背景来自同一视频画面，放大填满横屏画布后模糊；原竖屏画面等比缩放到画布高度并居中叠放。
- 已经存在 `原名-竖屏原版.mp4` 时默认认为处理过，跳过；设置 `portrait_overwrite=true` 后才重新处理。
- 默认保留竖屏原版备份；设置 `delete_portrait_source=true` 后不保留备份。

视频版本优先级:

- 同一基础文件同时存在普通版、`-弹幕版`、`-竖屏原版` 时，下游字幕、高光、切片、字幕烧录、封面和投稿清单优先使用 `-弹幕版`。
- 没有弹幕版时优先使用普通主视频；`-竖屏原版` 只作为兜底，避免竖屏备份被误当作主视频继续处理。
- `_subbed.mp4` 成片也遵循同样规则，例如 `xxx-弹幕版_subbed.mp4` 会优先于 `xxx_subbed.mp4`。

弹幕压制规则:

- 匹配同目录同名 `.mp4` + `.xml`。
- 输出 `原名-弹幕版.mp4`。
- 已存在输出时默认跳过。
- 生成 ASS 时会读取源视频实际显示分辨率，例如竖屏 `720x1280` 会使用 `--resolution 720x1280`。

弹幕 XML→ASS 前置转换规则:

- 只处理与视频同名、且缺少同名 `.ass` 的 XML；已有 ASS 时跳过（幂等，可重复运行）。
- DanmakuFactory 缺失或单个文件转换失败只提示，不影响其余文件和后续步骤。
- XML 源文件只读，转换只产出 ASS，不删除、不修改 XML。

## 4. `step2_subtitle`: 字幕识别

入口: `core/generate_subtitles.py`

字段:

| 字段 | 类型 | 默认值 | 当前用途 |
| --- | --- | --- | --- |
| `engine` | string | `funasr` | ASR 引擎。常用值: `funasr`、`portable`、`whisper`、`belle` |
| `model` | string | `SenseVoiceSmall` | FunASR/Whisper 模型名或模型路径 |
| `language` | string | `zh` | 识别语言 |
| `speaker_diarization` | boolean | `false` | FunASR/portable 时追加 `--speaker` |
| `punc` | boolean | `true` | FunASR/portable 时控制是否禁用标点恢复；`false` 会追加 `--no-punc` |
| `auto_lang` | boolean | `false` | Whisper 时追加 `--auto-lang` |
| `belle_model` | string | 空 | Belle 引擎模型路径；设置后追加 `--model` |
| `vad` | boolean | `true` | 配置生成器和旧配置保留字段；当前 `auto_pipeline.py` 未直接传参 |
| `whisper_model` | string | 空 | 配置生成器兼容字段；当前一键流转主要使用 `model` |

示例:

```json
{
  "step2_subtitle": {
    "engine": "funasr",
    "model": "SenseVoiceSmall",
    "language": "zh",
    "vad": true,
    "speaker_diarization": false,
    "punc": true
  }
}
```

## 5. `step3_highlight`: 高光分析

入口: `core/generate_clips_combined.py`

字段:

| 字段 | 类型 | 默认值 | 当前用途 |
| --- | --- | --- | --- |
| `mode` | string | `llm` | 分析模式。可用值: `danmu`、`llm`、`combined`、`emotion`、`multi` |
| `prompt_dir` | string | 空 | 自定义提示词目录，设置后传给 `--prompts-dir` |
| `multi_sources` | string | 空 | `mode=multi` 时传给 `--multi-sources`，例如 `danmu,llm,emotion` |

示例:

```json
{
  "step3_highlight": {
    "mode": "llm",
    "prompt_dir": ""
  }
}
```

`Data_source.txt` 关键时间字段:

| 字段 | 含义 |
| --- | --- |
| `segment` | 源视频现实起始时间，通常来自文件名前缀，如 `01-04-03` |
| `timestamp` | 切片在该源视频内的时间范围，如 `00:02:23-00:03:22` |
| `real_timestamp` | 换算后的现实时间范围，如 `01:06:26-01:07:25` |

## 8. `step5_burn`: 字幕烧录

入口: `core/burn_subtitles.py`

字段:

| 字段 | 类型 | 默认值 | 当前用途 |
| --- | --- | --- | --- |
| `enabled` | boolean | `true` | 是否执行字幕烧录步骤；`false` 时一键流转和命令行流水线跳过步骤5 |
| `skip_asr` | boolean | `false` | 跳过切片 ASR，直接使用已有 SRT |
| `engine` | string | `whisper` | 切片补字幕 ASR 引擎 |
| `model` | string | `large-v3-turbo` | 切片补字幕模型 |
| `language` | string | `zh` | ASR 语言 |
| `font` | string | `MaokenAssortedSans` | 字体家族名或 `.ttf` / `.otf` 文件路径 |
| `font_size` | number | `80` | ASS 字号 |
| `color` | string | `&H00FFFFFF` | ASS 主文字颜色 |
| `outline_color` | string | `&H00000000` | ASS 描边颜色 |
| `outline` | number | `8` | 描边宽度 |
| `margin_v` | number | `80` 或 GUI 默认 `100` | 底部边距 |
| `margin_l` | number | `80` | 左边距 |
| `margin_r` | number | `80` | 右边距 |
| `max_line_chars` | number | `0` | 单行最大字符数；`0` 表示自动/不限制 |
| `orientation` | string | `auto` | 字幕布局方向，常用 `auto` |
| `shadow` | boolean | `false` | 是否启用阴影 |
| `shadow_color` | string | `black` | 阴影颜色；非 `black` 时会传给脚本 |
| `punc` | boolean | `true` | `false` 时追加 `--no-punc` |
| `speed` | string | `auto` | 非 `auto` 时传给 `--speed` |
| `vad` | boolean | `true` | 配置生成器和旧配置保留字段；当前 `auto_pipeline.py` 未直接传参 |

示例:

```json
{
  "step5_burn": {
    "skip_asr": false,
    "engine": "whisper",
    "model": "large-v3-turbo",
    "language": "zh",
    "font": "抖音美好体.otf",
    "font_size": 80,
    "outline": 5,
    "shadow": true,
    "shadow_color": "white",
    "margin_v": 100,
    "color": "&H00FFFFFF",
    "outline_color": "&H00000000"
  }
}
```

颜色说明: 当前字段直接传给 ASS/FFmpeg 相关脚本，格式通常为 `&HAABBGGRR`。

## 9. `step6_cover`: 封面生成

入口:

- `core/generate_covers.py`
- 可选新样式: `core/generate_covers_new.py`

字段:

| 字段 | 类型 | 默认值 | 当前用途 |
| --- | --- | --- | --- |
| `style` | string | `style1` | 封面样式；常用 `random_1_4` |
| `font` | string | `MaoKenShiJinHei-2.ttf` | 字体文件名、字体名或绝对路径 |
| `output_dir` | string | `{input_dir}/切片/封面` | 封面输出目录；会替换 `{input_dir}` |
| `match_subbed_only` | boolean | `true` | 配置/GUI 语义字段；当前 `auto_pipeline.py` 固定使用 `--match-subbed` |
| `use_new_style` | boolean | `false` | 为 `true` 时追加 `--use-new-style` |

封面抽帧来源:

- 封面背景帧**优先从同名原视频（未烧录字幕的切片）抽取**，避免封面带上烧录的字幕。
- 原视频不存在时才回退到 `_subbed.mp4` 本身抽帧。
- 视频匹配先按 `[segment] 标题` 精确匹配（标题来自 `Data_source.txt` 的 `title`），匹配不到再回退前缀模糊匹配。
- 抽帧位置: 固定取切片正中间帧（2026-09-10 起，不再随机；同一输入重新生成画面完全一致）。抽帧源是原始完整录播时按 `Data_source.txt` 绝对时间取切片区间中点，是切片文件时取文件正中间。

示例:

```json
{
  "step6_cover": {
    "style": "random_1_4",
    "font": "抖音美好体.otf",
    "output_dir": "{input_dir}/切片/封面",
    "match_subbed_only": true,
    "use_new_style": false
  }
}
```

## 10. `step7_upload`: 投稿清单与投稿默认参数

入口:

- `core/auto_pipeline.py`
- `gui_app_mobile.py`
- `web_console.py`
- `utils/bilibili_uploader.py`

字段:

| 字段 | 类型 | 默认值 | 当前用途 |
| --- | --- | --- | --- |
| `tid` | number | `217` 或界面默认值 | B 站分区 ID |
| `tid_name` | string | 空 | 人类可读分区名；主要用于配置说明 |
| `copyright` | string/number | `original` | `original` 转为 `1`，其他字符串通常转为 `2`；也可在部分路径直接使用数字 |
| `no_reprint` | boolean/number | `false` / `1` | 投稿接口参数；GUI 批量上传会传给 uploader |
| `title_rule` | string | `从文件名提取` | 说明字段；当前实际按切片文件名提取标题（优先 `_subbed.mp4`，无则原版） |
| `title_suffix_name` | string | `streamer_name` | 投稿标题前缀 `【】` 中使用的显示名；为空时使用主播名称 |
| `desc_template` | string | 空 | 说明/兼容字段；当前主流程自动拼接主页、直播间、`real_timestamp`、`summary` |
| `cover_rule` | string | `{input_dir}/切片/封面/[{timestamp}] {title}.jpg` | 说明/兼容字段；当前实际按切片文件名前缀匹配封面 |
| `tags` | array[string] | `[]` | 投稿标签，建议不超过 10 个 |

投稿清单生成规则:

- 切片视频目录优先扫描 `_subbed.mp4`（已烧录字幕版）；**没有字幕版时回退使用原版切片 mp4**。
- 弹幕版优先过滤（同基础名存在 `-弹幕版` 时优先使用）。
- 封面按完整文件名前缀匹配（原版与字幕版指向同一封面）。

示例:

```json
{
  "step7_upload": {
    "tid": 27,
    "tid_name": "动画·综合",
    "copyright": "original",
    "no_reprint": false,
    "title_rule": "从文件名提取",
    "title_suffix_name": "主播短名",
    "desc_template": "",
    "cover_rule": "{input_dir}/切片/封面/[{timestamp}] {title}.jpg",
    "tags": ["虚拟主播", "ai切片", "主播名"]
  }
}
```

投稿简介实际拼接顺序:

1. `bilibili_links.space`，格式为 `{streamer_name}的个人主页：...`
2. `bilibili_links.live`，格式为 `{streamer_name}的直播间：...`
3. `Data_source.txt` 中匹配到的 `real_timestamp`，格式为 `直播时间：HH:MM:SS-HH:MM:SS`
4. `Data_source.txt` 中匹配到的 `summary`

投稿状态不放在主播配置里。投稿记忆写入每个录播目录下的 `upload_manifest.json`。

字段:

| 字段 | 类型 | 默认值 | 当前用途 |

```json
  "keywords": [

    "联动对象",
    "节目名"
  ]
}
```

LLM 高光分析会通过 `utils/streamer_prompts.py` 读取 `keywords`，并追加到主播提示词中。日常 Light GUI 和配置生成器的梗搜索结果会直接合并进 `keywords`；不再保存 `_meme_result`。

## 14. 维护规则

- 新增字段后，应同步更新本文件、`docs/AutoClip_技术复刻文档.md` 和配置生成器。
- 不要在主播配置中提交真实 API Key、Cookie、SENDKEY 等敏感信息。
- 路径建议使用绝对路径或 `{input_dir}` 占位符；跨机器迁移时优先检查字体路径、FFmpeg 路径和模型路径。
- `title_rule`、`desc_template`、`cover_rule` 当前不是主流程的强约束字段，维护时不要误以为改它们一定会改变自动生成逻辑。
- 投稿状态、投稿次数、BVID 和失败原因属于 `upload_manifest.json`，不要写入主播默认配置。
